Converting several images at once

At the heart of the project is a group of concurrently running conversion workers. These workers are handled by a ThreadPoolTaskScheduler and get continuously rescheduled, with a back-off delay if the queue has run dry.

Postgres plays a vital part in my approach to concurrency, with the task table acting as a queue for my workers. This is where Postgres truly shines with the following magical syntax: 

FOR UPDATE SKIP LOCKED

Four words that prevent

  • Duplicate processing
  • Deadlocks
  • Getting stalled by locked rows (compared to plain FOR UPDATE)

The first part FOR UPDATE ensures rows returned by SELECT are locked for modification (incl. further locking) for the duration of the transaction. However, because FOR UPDATE is a locker, it itself gets stalled by locked row matches. The exact opposite of what we want for concurrent workers. FOR UPDATE SKIP LOCKED sidesteps this issue by ignoring locked rows entirely as if they don't exist.

This way we the database both ensures tasks get locked to prevent double claims, but also continued immediate access for new worker queries.
